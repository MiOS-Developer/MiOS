# Tamagotchi terminal foundation

`mios-tamagotchi` is a runnable sprite preview and reusable Rust library for the
rendering/input portion of the Tamagotchi specifications. It does not implement
care, lifecycle, economy, persistence, social features or an MCP server.

## Run

From the source root, after building the native binary:

```sh
mios-tamagotchi --root .
mios-tamagotchi --root . --renderer half-block --color indexed
mios-tamagotchi --root . --renderer braille --scale 2
mios-tamagotchi --root . --snapshot
```

Installed use omits `--root` and resolves the normal MiOS vendor/host/user TOML
layers. The binary is registered in `[build.native.categories.apps]` for
`/usr/bin`; the separate image integration task verifies installed delivery.
Arrows and Tab/Shift+Tab select a frame and pause; Enter, Space or P toggle
animation; Q, Escape and Ctrl+C exit. Releases are ignored, and repeated pause
keys do not toggle repeatedly. Keyboard enhancements and mouse capture are not
enabled. Resizing recomputes the drawable viewport and fitting scale.

When either input or output is not a TTY, or TERM is empty/dumb, output is one
bounded ASCII snapshot even if graphics flags are supplied. `--snapshot` also
avoids raw mode on a TTY. Configuration errors fail before terminal initialization.
Ratatui's run lifecycle restores normal exits, returned errors and panics; abrupt
termination such as SIGKILL cannot run cleanup.

## Configuration and rendering contract

`[tamagotchi]` in `usr/share/mios/mios.toml` supplies renderer, color, scale,
tick_ms, four palette colors and background. Higher TOML layers override individual
fields. CLI renderer/color/scale override the merged values. Unknown fields,
invalid RGB colors, invalid scale and tick intervals outside 16..60000 ms fail.

Glyph choice and color depth are independent. Automatic glyph choice uses
half-blocks for a Unicode terminal and ASCII for Linux VT or an uncertain locale.
Explicit renderer selection overrides that heuristic; it cannot establish font
coverage. Linux VT is capped to ANSI colors, VT100/VT220 to monochrome, and
nonempty NO_COLOR disables colors even with an explicit RGB request. Color
heuristics observe the current output stream, including the terminal presented
by tmux, rather than assuming the outer emulator's capabilities.

Half-blocks pack two independently colored vertical pixels per cell. Quadrants
pack 2x2 and Braille packs 2x4 occupancy masks with one foreground color per cell;
for multicolor sprites they deliberately lose per-dot color. Transparent cells
leave the widget buffer untouched; partially occupied cells use the configured
background. ASCII uses only printable ASCII. The original two-frame sprite is
preview art, not an emulation of a branded character.

Scaling selects 1, 2, 4, 8 or 16 only when both cell dimensions fit after UI chrome
is removed. A fixed oversized scale shows a no-fit message rather than wrapping.
Packing uses ceiling division for odd dimensions and widened arithmetic. The
widget clips writes to its Ratatui buffer, without direct terminal output.

## Existing Inputd integration

The application consumes the ordinary key events generated by existing Inputd
terminal profiles. It adds no global context, reserved-button bindings or input
subscription socket. Existing explicit session routes can deliver those keys to
a local or remote tmux pane under the current ownership policy. The preview does
not open physical evdev devices and does not treat vpad as an input subscriber.

## Verification and handoff

Run the crate tests with the SSOT Linux target; host development can explicitly
select `--target x86_64-unknown-linux-gnu`:

```sh
cargo test --manifest-path tools/native/Cargo.toml -p mios-tamagotchi
cargo clippy --manifest-path tools/native/Cargo.toml -p mios-tamagotchi --all-targets -- -D warnings
```

The suite checks actual CLI snapshots and layered errors, independent capability
selection, Unicode mask orientation, two-color cells, clipping, invalid sprite
inputs, no-fit geometry, palette conversion and projected-key event kinds.
These checks do not certify real controller ownership or console font coverage.

Canonical tasks in `tasks.jsonl` carry ownership and evidence. After pulling
main, remote agents claim their separate lane before editing:

- task_3703: MiOS-DEV image delivery, static/native installation and app launch.
- task_3704: bootstrap configurator round-trip for the TOML fields; preserve repository ownership.
- task_3705: real Linux VT, UTF-8 terminal, tmux/controller ownership and restoration checks.
- task_3706: deterministic care/lifecycle and atomic versioned persistence before social features.

The research baseline is Ratatui 0.30.2 with its Crossterm 0.29 backend and Rust
1.88 or newer. The native widget uses Ratatui's quadrant symbol table. Reference
implementations: [Ratatui Canvas](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.2/ratatui-widgets/src/canvas.rs),
[quadrant symbols](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.2/ratatui-core/src/symbols/pixel.rs),
[supports-color](https://github.com/zkat/supports-color), and
[Inputd navigation](https://github.com/MiOS-Developer/MiOS/blob/855a852d08e063596036a41dae77cb81a2bf372d/tools/native/mios-inputd/src/nav.rs).
